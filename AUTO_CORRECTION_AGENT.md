# Auto-Correction Agent Documentation

## Overview

The Auto-Correction Agent is an intelligent system that automatically detects code issues and generates pull requests with fixes. It integrates with GitHub Actions, performs comprehensive validation, and maintains detailed audit trails.

## Architecture

### Core Components

#### 1. **Issue Detector** (`detector.rs`)
- Scans entire codebase for potential issues
- Classification system:
  - Compilation errors
  - Logic errors
  - Style violations
  - Memory safety issues
  - Performance concerns
  - Security vulnerabilities
  - Documentation gaps

**Features:**
- Confidence scoring (0.0-1.0)
- Severity levels (Info → Critical)
- Suggested fixes for each issue
- Grouping by type and file

#### 2. **Code Corrector** (`corrector.rs`)
- Applies semantic-aware transformations
- Strategy pattern for extensibility
- Built-in strategies:
  - `SyntaxFixStrategy`: Handles compilation errors
  - `StyleFixStrategy`: Applies code formatting

**Capabilities:**
- Syntax validation
- Batch file processing
- Test case generation
- Automated formatting

#### 3. **Validator** (`validator.rs`)
- Multi-level validation pipeline
- Compilation verification
- Test suite execution
- Safety analysis
- Quality scoring

**Validation Results:**
- Detailed findings with severity levels
- Quality score calculation (0.0-1.0)
- Comprehensive markdown reports
- Timestamp tracking

#### 4. **PR Generator** (`pr_generator.rs`)
- Creates professional pull requests
- GitHub API integration
- Metadata management
- Commit detail tracking

**Generated Content:**
- Descriptive PR titles
- Detailed change descriptions
- Issue linking
- Automatic labeling

## Integration Points

### GitHub Actions Workflow
Location: `.github/workflows/auto-correction.yml`

**Workflow Stages:**
1. **Issue Detection**
   - Runs `cargo check`
   - Executes `clippy` analysis
   - Performs `cargo-audit` security scan

2. **Auto-Correction**
   - Creates feature branch
   - Applies corrections
   - Validates changes
   - Creates atomic commits

3. **Pull Request Creation**
   - Generates PR with details
   - Adds validation results
   - Links related issues
   - Applies labels

4. **Notification**
   - Reports completion status
   - Provides summary metrics

### Trigger Options
- **Scheduled**: Daily at 2 AM UTC
- **Manual**: Via `workflow_dispatch` with severity selection

## Configuration

### Default Settings
```rust
AutoCorrectorConfig {
    auto_pr_enabled: true,           // Create PRs automatically
    min_confidence: 0.85,            // Minimum confidence for auto-corrections
    target_branch: "main",           // Target branch for PRs
    validate_before_pr: true,        // Validate before PR creation
}
```

### Customization
Modify configuration in workflow trigger inputs:
- `severity`: Minimum issue severity to correct (info/warning/error/critical)
- Branch settings in workflow file
- Validation thresholds

## Issue Detection

### Severity Levels
- **Info**: Informational findings
- **Warning**: Non-blocking concerns
- **Error**: Blocking issues requiring fixes
- **Critical**: Security/safety critical issues

### Confidence Scoring
- 0.9-1.0: Very high confidence
- 0.75-0.9: High confidence
- 0.6-0.75: Medium confidence
- < 0.6: Low confidence (usually not corrected)

## Validation Process

### Quality Scoring Formula
```
Base Score: 1.0
- Warning: -0.1 per finding
- Error: -0.25 per finding
- Critical: -0.5 per finding
Final Score: max(0.0, base - penalties)
```

### Pass Criteria
- Compilation successful
- All tests pass
- Quality score > 0.75

## Usage

### Automatic Execution
Agent runs on schedule (daily at 2 AM UTC). PRs are created automatically if issues are detected and corrections pass validation.

### Manual Trigger
```bash
# Via GitHub UI
Actions → Auto-Correction Agent → Run workflow
# Select severity level (info/warning/error/critical)
```

### Integration in CI/CD
The workflow can be customized to:
- Run on pull requests for validation
- Trigger after merges to main
- Execute on demand for specific branches

## Best Practices

### For Teams
1. **Review PRs thoroughly** - Always manually review auto-generated PRs
2. **Monitor confidence scores** - Adjust thresholds based on false positives
3. **Customize strategies** - Add domain-specific correction strategies
4. **Regular audits** - Review validation findings periodically

### For Quality
1. **Maintain test suite** - Ensure comprehensive test coverage
2. **Clear build output** - Fix warnings and errors proactively
3. **Security updates** - Keep dependencies current
4. **Documentation** - Keep code well-documented

## Extensibility

### Adding Custom Strategies
1. Implement `CorrectionStrategy` trait
2. Define `can_handle()` logic
3. Implement `apply()` transformation
4. Register in `CodeCorrector`

### Custom Issue Types
Extend `IssueType` enum and create corresponding detection logic in `IssueDetector`.

### Custom Validators
Implement validation stages in `Validator::validate()` method.

## Troubleshooting

### No Issues Detected
- Check workflow logs for scan errors
- Verify project compiles correctly
- Check clippy warnings configuration

### PR Not Created
- Verify validation passed (check logs)
- Confirm `auto_pr_enabled: true` in config
- Check GitHub token permissions

### False Positives
- Adjust `min_confidence` threshold
- Review issue categorization
- Consider disabling specific detectors

## Performance Considerations

- Workflow runs take 5-10 minutes typically
- Caching reduces build times significantly
- Async operations prevent blocking
- Batch processing optimizes file modifications

## Security

- Uses GitHub token with minimal required permissions
- No credentials stored in repository
- All changes are atomic (single commit)
- Complete audit trail in PR and commit messages
- Validation prevents unsafe changes
